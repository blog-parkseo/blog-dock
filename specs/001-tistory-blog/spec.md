# Feature Specification: 티스토리형 블로그 서비스

**Created**: 2026-10-07

**Status**: Draft

**Input**: User description: "spec kit로 하네스 이용할거고, 기능명세서 다시 한 번 작성해서 해당 저장소로 올려줘" — 원본: 「티스토리형 블로그 요구사항 명세서」(2026-10-05), 「티스토리형 블로그 통합 기능명세서 v0.2」

## 읽는 법

- **기능 ID**: `영역코드-번호`(예: `POST-03`). 팀 통합 명세서와 같은 ID이며, 계획·작업·이슈·커밋에서도 그대로 쓴다.
- **명세 등급**: 기능마다 팀 명세서의 등급을 붙인다. P0 필수(24개), P1 권장(24개), P2 확장(23개).
- **스토리 우선순위**: 아래 사용자 스토리의 Priority(P1, P2, …)는 Spec Kit의 구현 순서다. 팀 명세서의 P0/P1/P2와 다르므로, 스토리 제목 옆에 어떤 명세 등급 기능을 묶었는지 함께 적는다.
- **선택 항목**: 팀이 "하나를 골라 구현"하기로 한 8개 항목은 이 서비스에서 고른 방식으로 규칙을 적었다(아래 [선택 항목](#선택-항목-이-서비스의-결정)).
- **용어**: 비회원(로그인 안 함), 회원(로그인함), 블로그 주인(그 블로그를 개설한 회원), 서비스 관리자(운영자가 지정한 계정). 블로그 주인은 역할이 아니라 블로그마다 판단하는 상태다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 가입하고 내 블로그를 연다 (Priority: P1 · 명세 P0)

처음 온 사람이 카카오 계정으로 가입·로그인하고, 블로그 주소와 이름을 정해 자기 블로그를 만든다. 블로그 이름·소개·프로필 이미지를 꾸미고, 다 쓰면 로그아웃한다.

**Why this priority**: 블로그가 있어야 글을 쓸 수 있다. 모든 흐름의 시작점이다.

**Independent Test**: 새 계정으로 로그인 → 블로그 개설 → 블로그 메인 접속 → 정보 수정 → 로그아웃까지 해 보면 확인된다.

**Acceptance Scenarios**:

1. **Given** 비회원, **When** 카카오로 로그인에 성공하면, **Then** 일반 회원이 되고 로그인 전에 보던 화면(없으면 홈)으로 돌아간다.
2. **Given** 로그인 중 취소하거나 실패함, **When** 결과 화면으로 돌아오면, **Then** 아무것도 바뀌지 않고 실패 이유를 알린다.
3. **Given** 블로그가 없는 회원, **When** 주소 `my-dog`과 이름을 입력해 개설하면, **Then** 블로그가 만들어지고 새 블로그나 글쓰기로 간다. 개설 화면에는 "주소는 나중에 바꿀 수 없다"는 안내가 있다.
4. **Given** 이미 쓰이는 주소나 예약어(`admin` 등), 규칙에 어긋나는 주소(`-abc`, `ab`, `ABC`), **When** 입력하면, **Then** 입력 단계에서 어떤 이유로 쓸 수 없는지 알린다.
5. **Given** 이미 블로그가 1개 있는 회원, **When** 블로그를 하나 더 만들려고 하면, **Then** 개설을 막는다.
6. **Given** 블로그 주인, **When** 이름·소개·프로필 이미지를 바꾸면, **Then** 바로 반영되고 주소는 바꿀 수 없다. 소개가 비면 소개 자리를 숨기고, 프로필 이미지가 없으면 기본 이미지를 보여 준다.
7. **Given** 로그인한 회원, **When** 로그아웃하면, **Then** 비회원이 되어 홈이나 보던 공개 화면으로 가고, 글쓰기·관리 화면에 들어갈 수 없다.

### User Story 2 - 글을 쓰고 발행하고 고친다 (Priority: P2 · 명세 P0)

블로그 주인이 제목과 본문(문단 제목, 굵게, 목록, 인용, 코드 블록, 링크, 이미지)을 쓰고, 카테고리·태그·공개 범위를 정해 발행한다. 발행한 글을 고치거나 지운다.

**Why this priority**: 글이 블로그의 핵심 가치다. Story 1 다음으로 꼭 있어야 한다.

**Independent Test**: 블로그 주인으로 이미지가 든 글을 발행 → 상세 화면 확인 → 수정 → 비공개 전환 → 삭제를 해 보면 확인된다.

**Acceptance Scenarios**:

1. **Given** 블로그 주인, **When** 새 글 쓰기를 열면, **Then** 이전에 쓰던 내용 없이 빈 상태로 시작한다.
2. **Given** 제목과 본문이 모두 비어 있음, **When** 발행하면, **Then** 발행되지 않고 첫 번째 문제(제목)만 알린다. 제목이 공백뿐이어도 빈 것으로 본다.
3. **Given** 제목·본문을 채우고 카테고리를 고르지 않음, **When** 발행하면, **Then** 글은 '미분류'로 들어가고 글 상세 화면으로 간다. 공감·댓글·조회수는 0이다.
4. **Given** 발행 버튼을 빠르게 여러 번 누름, **When** 요청이 처리되면, **Then** 글은 하나만 생긴다.
5. **Given** 이미지 3장을 골라 본문에 넣음, **When** 업로드되면, **Then** 커서 위치에 고른 순서대로 들어간다. 이미지가 아닌 파일이나 크기 상한을 넘는 파일은 이유와 함께 거절되고 본문은 그대로다.
6. **Given** 발행한 글, **When** 제목과 본문을 고쳐 저장하면, **Then** 글 주소, 처음 발행일, 공감·댓글·조회수, 목록 순서는 그대로다. 다시 수정하러 열어도 서식이 남아 있다.
7. **Given** 공개 글, **When** 비공개로 바꾸면, **Then** 블로그 주인 말고는 아무도 그 글을 목록·검색·홈·사이드바 글 수에서 볼 수 없고, 주소로 열면 404다.
8. **Given** 블로그 주인, **When** 글 삭제를 누르고 한 번 더 확인하면, **Then** 글과 댓글·공감·저장·알림이 함께 사라지고 블로그 메인이나 글 관리로 간다. 옛 주소는 404다.
9. **Given** 블로그 주인이 아닌 사람, **When** 글 수정·삭제 주소를 직접 열거나 요청을 직접 보내면, **Then** 비회원은 로그인 안내, 회원은 403을 받는다.

### User Story 3 - 다른 사람이 홈에서 글을 발견하고 읽는다 (Priority: P3 · 명세 P0)

누구나(비회원 포함) 홈에서 플랫폼 전체의 최신 글을 보고, 글을 눌러 읽고, 블로그 메인에서 카테고리·태그별로 둘러보고, 블로그 안에서 검색한다.

**Why this priority**: 쓴 글이 읽혀야 블로그 플랫폼이 된다. Story 1·2가 만든 글을 소비하는 흐름이다.

**Independent Test**: 다른 블로그에 공개 글 15개와 비공개 글 1개가 있을 때, 비회원으로 홈 → 글 상세 → 블로그 메인 → 카테고리 → 태그 → 블로그 내 검색을 해 보면 확인된다.

**Acceptance Scenarios**:

1. **Given** 여러 블로그의 공개 글, **When** 비회원이 홈을 열면, **Then** 공개 글이 처음 발행 시각 기준 최신순으로 보이고, 각 글에 제목·블로그 이름·발행일·본문 요약이 있다. 비공개 글과 관리자가 숨긴 글은 없다.
2. **Given** 홈에서 더보기(또는 무한 스크롤), **When** 다음 글을 불러오면, **Then** 같은 글이 두 번 나오거나 빠지지 않는다.
3. **Given** 공개 글 15개인 블로그, **When** 블로그 메인을 열면, **Then** 최신순 한 페이지 10개(권장)로 나뉘고, 마지막 페이지를 넘으면 오류가 아니라 빈 목록이다.
4. **Given** 블로그의 어느 화면이든, **When** 열면, **Then** 같은 사이드바(블로그 이름·프로필, '전체 글'이 맨 위·'미분류'가 맨 아래인 카테고리 목록과 글 수)가 붙는다. 미분류 글이 없으면 미분류는 숨긴다.
5. **Given** 글 상세, **When** 열면, **Then** 제목·발행일·카테고리·본문·태그·공감 수·댓글이 보이고, 본문에 들어 있는 스크립트는 실행되지 않는다.
6. **Given** 카테고리나 태그, **When** 누르면, **Then** 그 블로그에서 해당 글만 최신순으로 보이고, 카테고리·태그마다 고유한 주소가 있다.
7. **Given** 블로그 내 검색, **When** `  Dog  `을 입력하면, **Then** 앞뒤 공백을 빼고 대소문자 구분 없이 제목·본문·태그에서 찾는다. 공백만 입력하면 검색하지 않는다. 결과가 없으면 없다고 알리고 검색어를 남겨 둔다. 결과 주소를 공유하면 같은 결과가 나온다.
8. **Given** 남의 비공개 글, 없는 글, 다른 블로그 주소를 붙인 글, **When** 주소로 열면, **Then** 모두 404다.

### User Story 4 - 읽은 글에 댓글과 공감을 남긴다 (Priority: P4 · 명세 P0)

회원이 글에 댓글을 쓰고 공감을 누른다. 블로그 주인은 자기 블로그의 댓글을 정리한다.

**Why this priority**: P0 흐름의 마지막 고리(읽기 → 반응)다. 이 스토리까지 끝나면 P0 한 바퀴가 돈다.

**Independent Test**: 회원 A의 글에 회원 B가 댓글·공감 → A가 B의 댓글 삭제 → 비회원이 공감 시도를 해 보면 확인된다.

**Acceptance Scenarios**:

1. **Given** 비회원, **When** 댓글 쓰기나 공감을 누르면, **Then** 로그인으로 안내하고 로그인 후 원래 글로 돌아온다.
2. **Given** 회원, **When** 1~1,000자 댓글을 등록하면, **Then** 작성자 닉네임과 작성 날짜·시각이 함께 작성순으로 보이고 댓글 수가 늘어난다. 등록을 연달아 눌러도 한 번만 등록된다.
3. **Given** 자기 댓글, **When** 삭제하고 확인하면, **Then** 댓글이 사라진다. 남의 댓글에는 삭제가 없고, 요청을 직접 보내도 403이다.
4. **Given** 블로그 주인, **When** 자기 글에 달린 남의 댓글을 지우면, **Then** 지워진다. 남의 댓글을 수정할 수는 없다.
5. **Given** 회원, **When** 공감을 누르고 다시 누르면, **Then** 공감과 취소가 바로 반영되고, 새로고침해도 공감 수가 실제 개수와 같다.

### User Story 5 - 접근 제어와 서비스 관리자 영역 (Priority: P5 · 명세 P0)

권한이 없는 행동은 어떤 경로로 시도해도 막히고, 서비스 관리자만 들어갈 수 있는 관리 영역이 있다. 오류가 나면 사용자에게 이해할 수 있게 알린다.

**Why this priority**: 다른 모든 스토리가 안전하게 동작하기 위한 바탕이다. 각 스토리 구현 중에도 함께 확인한다.

**Independent Test**: 비회원·회원·블로그 주인·서비스 관리자 계정으로 권한표(아래 COM-01)의 행동을 주소 직접 입력과 직접 요청으로 시도해 보면 확인된다.

**Acceptance Scenarios**:

1. **Given** 일반 회원, **When** 관리 영역 주소를 직접 입력하면, **Then** 403이다. 비회원이면 로그인 안내다.
2. **Given** 서비스 첫 시작, **When** 관리 영역을 보면, **Then** 서비스 관리자 계정이 하나 이상 있다. 가입이나 화면으로는 서비스 관리자가 될 수 없다.
3. **Given** 잘못된 입력, **When** 저장하면, **Then** 어느 항목이 왜 잘못됐는지 알리고 입력한 내용은 지우지 않는다.
4. **Given** 예상하지 못한 오류, **When** 발생하면, **Then** 내부 정보(오류 위치, 서버 구성)는 보이지 않고 잠시 후 다시 시도하라고 알린다.
5. **Given** 로그인 만료 중 글을 쓰고 있었음, **When** 다시 로그인하면, **Then** 원래 화면으로 돌아오고 쓰던 내용을 잃지 않는다.

### User Story 6 - 쓸 만한 블로그로 다듬기 (Priority: P6 · 명세 P1)

임시저장, 대표 이미지, 조회수, 이전·다음 글, 하위 카테고리와 순서, 태그 목록, 댓글 수정, 방명록, 공유, 로그인 유지, 블로그 개설 안내, 회원정보 수정으로 블로그 쓰기·읽기를 편하게 만든다.

**Why this priority**: P0 흐름이 돈 다음, 실제로 쓰기 좋게 만드는 기능들이다.

**Independent Test**: 글을 임시저장 후 다시 열어 이어 쓰기 → 대표 이미지 지정 → 하위 카테고리 글 확인 → 방명록 작성 → 글 주소 복사를 해 보면 확인된다.

**Acceptance Scenarios**:

1. **Given** 임시저장된 글이 있음, **When** 새 글 쓰기를 열면, **Then** 이어 쓸지 묻는다. 발행하면 그 임시저장은 지워진다.
2. **Given** 대표 이미지를 고르지 않은 글, **When** 목록에 보이면, **Then** 본문 첫 이미지가 대표 이미지이고, 이미지가 없으면 대표 이미지 없이 보인다.
3. **Given** 상위 카테고리 아래 하위 카테고리가 있음, **When** 상위를 누르면, **Then** 하위 글까지 함께 보이고 글 수도 합친 값이다. 하위가 있는 상위는 바로 지울 수 없다.
4. **Given** 비공개 글이 사이에 있음, **When** 다른 사람이 이전·다음 글로 이동하면, **Then** 비공개 글을 건너뛴다.

---

### User Story 7 - 구독하고 피드로 모아 본다 (Priority: P7 · 명세 P1)

회원이 마음에 드는 블로그를 구독하고, 구독한 블로그의 새 글을 피드에서 모아 본다. 블로그에는 구독자 수가 보인다.

**Why this priority**: 다시 찾아오게 만드는 기능이다. P0 이후 가장 가치가 크다.

**Independent Test**: 회원 A가 블로그 B를 구독 → B가 새 글 발행 → A의 피드에 표시 → 구독 해제를 해 보면 확인된다.

**Acceptance Scenarios**:

1. **Given** 회원, **When** 자기 블로그를 구독하려 하면, **Then** 구독할 수 없다.
2. **Given** 구독한 블로그가 없음, **When** 피드를 열면, **Then** 그 사실을 알리고 다른 블로그를 둘러보게 안내한다.
3. **Given** 구독한 블로그의 구독자 공개 글(POST-12, P2를 구현한 경우), **When** 피드를 열면, **Then** 그 글이 보인다. 구독을 해제하면 그 글은 피드와 검색에서 빠진다.

### User Story 8 - 홈에서 인기 글·주제별 글과 통합 검색으로 탐색한다 (Priority: P8 · 명세 P1)

방문자가 홈에서 인기 글 순위와 주제별 글을 보고, 플랫폼 전체에서 글과 블로그를 검색한다.

**Why this priority**: 새 블로그와 글을 발견하는 길을 넓힌다.

**Independent Test**: 최근 7일 공감·댓글이 다른 글 3개를 만들어 인기 글 순서 확인 → 블로그 주제를 정하고 주제별 글 확인 → 통합 검색으로 블로그 이름 찾기를 해 보면 확인된다.

**Acceptance Scenarios**:

1. **Given** 최근 7일 공감+댓글 수가 다른 공개 글들, **When** 인기 글을 보면, **Then** 합계가 큰 순서로 보이고 숨긴 글·비공개 글은 없다. 인기 글이 하나도 없으면 빈 상태나 최신 글을 보여 준다.
2. **Given** 주제를 '여행'으로 정한 블로그, **When** 홈에서 '여행'을 고르면, **Then** 그 블로그의 공개 글이 최신순으로 보이고, 주제마다 고유한 주소가 있다.
3. **Given** 통합 검색, **When** 검색어를 입력하면, **Then** 공개 글과 이용 제한되지 않은 블로그(이름·소개)가 나오고, 글 결과에는 어느 블로그의 글인지 보인다.

### User Story 9 - 블로그 주인의 관리 화면과 서비스 관리자의 제재 (Priority: P9 · 명세 P1)

블로그 주인은 자기 글과 댓글을 한곳에서 관리한다. 서비스 관리자는 문제 회원의 이용을 제한하고 문제 글·댓글을 숨긴다.

**Why this priority**: 운영할 수 있는 서비스가 되기 위한 기능이다.

**Independent Test**: 관리자가 회원 A를 3일 제한·글 하나 숨김 → A가 로그인 시도(막힘·사유 확인) → 기한 후 자동 해제 → A의 글 관리에서 숨김 사유 확인을 해 보면 확인된다.

**Acceptance Scenarios**:

1. **Given** 블로그 주인, **When** 내 글 관리를 열면, **Then** 공개·비공개·임시저장 글이 상태별로 구분돼 보이고, 거기서 수정·삭제·공개 범위 변경을 할 수 있다.
2. **Given** 관리자가 사유와 기한을 정해 회원을 제한함, **When** 그 회원이 로그인하면, **Then** 막히고 사유와 기한을 안내받는다. 기한이 지나면 자동으로 풀린다.
3. **Given** 관리자가 글을 숨김, **When** 다른 사람이 주소로 열면, **Then** 404다. 글쓴이에게는 숨김 사실과 사유가 보이고, 숨김을 풀면 위치·수치·주소가 원래대로 돌아온다.
4. **Given** 관리자가 댓글을 숨김, **When** 다른 사람이 글을 보면, **Then** '관리자가 숨긴 댓글'로 표시된다.

### User Story 10 - 확장 기능 (Priority: P10 · 명세 P2)

회원 탈퇴, 블로그 꾸미기·삭제, 구독자 공개 글, 예약 발행, 카테고리 비공개, 태그 관리, 답글, 비밀댓글, 댓글 허용 설정, 저장, 알림, 맞구독, 추천 블로그, 인기 블로거, 랭킹 전체보기, 방문자 통계, 스팸·차단, 신고, 블로그 이용 제한, 공지·관리 이력·대시보드를 여유가 있을 때 하나씩 더한다.

**Why this priority**: 있으면 좋지만 없어도 티스토리형 블로그로 동작한다. 각 기능은 서로 독립적으로 추가할 수 있다.

**Independent Test**: 기능마다 아래 기능 요구사항의 규칙 하나하나를 그대로 시나리오로 확인한다.

**Acceptance Scenarios**:

1. **Given** 답글이 달린 댓글, **When** 작성자가 지우면, **Then** '삭제된 댓글'로 표시되고 답글은 남는다.
2. **Given** 예약 발행 시각을 정한 글, **When** 그 시각이 되면, **Then** 자동으로 공개되고, 목록에서는 실제 공개된 시각이 발행일이다. 그 전까지는 주인에게만 보인다.
3. **Given** 내가 내 글에 댓글을 씀, **When** 알림 목록을 보면, **Then** 내 행동으로 생긴 알림은 없다.
4. **Given** 서로 구독한 두 회원, **When** 구독 버튼을 보면, **Then** '서로 구독' 상태로 보인다. 한쪽이 해제하면 확인을 받고 내 구독만 취소되며 상대에게 알림은 가지 않는다.

---

### Edge Cases

- 블로그 주소 경계값: 3자·33자는 거절, 4자·32자는 허용. 대문자, 하이픈으로 시작·끝, 예약어, 삭제된 블로그가 쓰던 주소는 거절한다.
- 글 제목 경계값: 앞뒤 공백을 뺀 뒤 0자는 발행 불가, 100자는 허용, 101자는 거절한다.
- 같은 제목의 글을 두 번 발행하면 서로 다른 글 주소를 가진다. 한글 제목도 주소로 깨지지 않고 열린다.
- 같은 발행 시각의 글이 여러 개면 나중에 만든 글이 위에 온다.
- 마지막 페이지를 넘는 페이지 번호를 요청하면 오류가 아니라 빈 목록이다.
- 태그를 11개 달려고 하면 막는다. 같은 태그를 두 번 달면 한 번만 달린다.
- 카테고리를 지우면 소속 글이 미분류로 옮겨진다. '전체 글'과 '미분류'는 이름을 바꾸거나 지울 수 없다.
- 이미지 확장자로 위장한 이미지가 아닌 파일은 거절한다. GIF는 움직임이, 휴대폰 사진은 찍힌 방향이 유지된다.
- 업로드가 실패하면 기존 이미지와 본문은 그대로다.
- 글을 삭제하는 도중 실패해도 댓글만 지워지고 글은 남는 식의 일부 처리 상태가 없다.
- 로그인한 사용자가 다른 사이트를 방문해도 그 사이트가 사용자 대신 글을 쓰거나 지울 수 없다.
- 이용 제한된 회원이 이미 로그인한 상태였다면, 다음 행동부터 막힌다.
- 서비스 관리자는 다른 서비스 관리자를 제재할 수 없다.

## Requirements *(mandatory)*

요구사항 ID는 팀 통합 기능 ID를 그대로 쓰고, 기능 안의 규칙은 `-1`, `-2`로 나눈다. 괄호 안은 명세 등급이다.

### 공통 정책 (모든 기능에 적용)

#### 권한

- **COM-01** (P0) 접근 제어: 모든 행동은 아래 권한표를 따른다. 주소를 직접 입력하거나 요청을 직접 보내도 같은 결과여야 한다.

  | 행동 | 비회원 | 회원 | 블로그 주인 | 서비스 관리자 |
  | --- | --- | --- | --- | --- |
  | 공개 글 읽기, 홈·검색 | ○ | ○ | ○ | ○ |
  | 비공개 글 읽기 | ✕ | ✕ | 자기 것 | 제재에 필요한 범위 |
  | 댓글 쓰기 | ✕ | ○ | ○ | ○ |
  | 댓글 수정 | ✕ | 자기 것 | 자기 것 | 자기 것 |
  | 댓글 삭제 | ✕ | 자기 것 | 자기 블로그의 모든 댓글 | 숨김 처리 |
  | 공감·구독·저장 | ✕ | ○ | ○ | ○ |
  | 블로그 개설 | ✕ | ○ | ○ | ○ |
  | 글·카테고리·태그·블로그 설정, 블로그 관리 | ✕ | ✕ | 자기 블로그 | 자기 블로그 |
  | 서비스 관리 | ✕ | ✕ | ✕ | ○ |

  - **COM-01-1**: 비회원이 로그인이 필요한 행동을 하면 로그인으로 안내하고, 로그인 후 원래 화면으로 돌아간다.
  - **COM-01-2**: 로그인했지만 권한이 없으면 403이다.
  - **COM-01-3**: 없는 블로그·글·카테고리와 삭제된 글은 404다. 남의 비공개 글도 존재를 숨기기 위해 404다.
  - **COM-01-4**: 서비스 관리자도 남의 글·댓글·블로그 내용을 수정할 수 없다.
- **COM-02** (P0) 오류 처리:
  - **COM-02-1**: 404와 403을 구분해 알리고, 홈이나 이전 화면으로 돌아갈 길을 준다.
  - **COM-02-2**: 입력이 잘못되면 어느 항목이 왜 잘못됐는지 알리고, 입력한 내용은 지우지 않는다.
  - **COM-02-3**: 예상하지 못한 오류에도 내부 정보를 보여 주지 않고, 잠시 후 다시 시도하라고 알린다.

#### 공개 범위

- **POL-01-1**: 모든 글은 공개 또는 비공개다. 기본값은 공개이며 발행 후에도 바꿀 수 있다. 확장 공개 범위인 구독자 공개는 P2(POST-12)에서 더한다.
- **POL-01-2**: 비공개 글은 블로그 주인만 볼 수 있고, 다른 사람이 주소로 열면 404다.
- **POL-01-3**: 볼 수 없는 글은 블로그 글 목록, 카테고리·태그 목록, 검색, 홈, 인기 글, 피드, 사이드바, 글 개수에서 모두 빠진다.

#### 블로그 주소와 글 주소

- **POL-02-1**: 블로그 주소는 개설할 때 회원이 직접 입력하며 블로그 이름과 별개다.
- **POL-02-2**: 영문 소문자·숫자·하이픈만, 4~32자, 하이픈으로 시작하거나 끝낼 수 없다.
- **POL-02-3**: 다른 블로그의 주소와 예약어(login, admin, api 등)는 쓸 수 없고, 어긋나면 이유를 알린다.
- **POL-02-4**: 블로그 주소는 개설 후 바꿀 수 없고, 블로그가 삭제돼도 영구 예약된다.
- **POL-02-5**: 블로그의 모든 화면(메인, 글, 카테고리, 태그, 검색 결과)은 그 블로그의 서브도메인(`블로그주소.서비스주소`) 아래에 있고, 여러 블로그를 오가도 로그인이 유지된다.
- **POL-03-1**: 글 주소는 제목 기반이며 처음 발행할 때 정해지고, 제목이나 내용을 수정해도 바뀌지 않는다.
- **POL-03-2**: 같은 블로그 안에서 글 주소는 겹치지 않는다. 같은 제목이어도 다른 주소를 가지며, 한글 제목도 깨지지 않고 열린다.
- **POL-03-3**: 다른 블로그 주소를 붙여 글에 접근하면 404다.

#### 목록

- **POL-04-1**: 글 목록은 처음 발행 시각 기준 최신순이며, 수정해도 순서가 바뀌지 않는다. 시각이 같으면 나중에 만든 글이 위다.
- **POL-04-2**: 블로그 글 목록(카테고리·태그·검색 결과 포함)은 페이지로 나눈다. 한 페이지 10개를 권장한다.
- **POL-04-3**: 홈 최신 글·피드는 더보기나 무한 스크롤로 보여 줘도 되지만, 같은 글이 두 번 나오거나 빠지면 안 된다.
- **POL-04-4**: 마지막 페이지를 넘으면 오류가 아니라 빈 목록이다. 목록이 비면 빈 상태임을 알린다.
- **POL-04-5**: 목록과 글 개수는 보는 사람이 볼 수 있는 글만 센다.

#### 글자 수 제한 (앞뒤 공백을 잘라낸 뒤 센다)

- **POL-05-1**: 글 제목 1~100자, 비면 발행 불가. 글 본문은 비면 발행 불가.
- **POL-05-2**: 댓글·방명록 1~1,000자.
- **POL-05-3**: 블로그 이름 1~40자, 카테고리 이름 1~20자, 글당 태그 최대 10개.

#### 파일 업로드

- **POL-06-1**: 이미지(jpg, png, gif, webp)만 받는다. 이미지가 아니거나 이미지로 위장한 파일은 거절하고 기존 상태를 유지한다.
- **POL-06-2**: 파일 크기 상한이 있고, 넘으면 거절하고 이유를 알린다.
- **POL-06-3**: 업로드가 실패하면 기존 이미지·본문을 그대로 둔다.
- **POL-06-4**: 이미지 비율과 GIF 움직임을 유지하고, 휴대폰 사진은 찍힌 방향대로 보인다.

#### 삭제 처리 (모든 삭제는 한 번 더 확인한 뒤 진행한다)

- **POL-07-1**: 글을 삭제하면 댓글·공감·저장·알림이 함께 사라지고, 옛 주소는 404다.
- **POL-07-2**: 답글이 달린 댓글을 삭제하면 '삭제된 댓글'로 표시하고 답글은 남긴다.
- **POL-07-3**: 카테고리를 삭제하면 소속 글은 미분류로 옮긴다. 하위 카테고리가 있으면 먼저 옮기거나 지워야 한다.
- **POL-07-4**: 태그를 삭제하면 글과의 연결만 끊고 글은 남긴다.
- **POL-07-5**: 블로그를 삭제하면 사용자에게는 사라지고 주소는 영구 예약된다.
- **POL-07-6**: 서비스 관리자의 제재는 삭제하지 않고 숨긴다. 해제하면 원래대로 보인다.

### 기능 요구사항: P0 (필수 24개)

#### AUTH 회원·인증

- **AUTH-01** (P0) 가입·로그인:
  - **AUTH-01-1**: 카카오 계정으로 가입·로그인한다. 가입하면 항상 일반 회원이 되고, 회원마다 닉네임이 있다.
  - **AUTH-01-2**: 로그인에 성공하면 로그인 전에 보던 화면으로, 없으면 홈으로 간다.
  - **AUTH-01-3**: 로그인에 실패하거나 취소하면 아무것도 바뀌지 않고 이유를 알린다.
- **AUTH-02** (P0) 로그아웃:
  - **AUTH-02-1**: 로그아웃하면 비회원 상태가 되고 홈이나 보던 공개 화면으로 간다.
  - **AUTH-02-2**: 로그아웃 후에는 글쓰기·관리 화면에 들어갈 수 없다.

#### BLOG 블로그

- **BLOG-01** (P0) 블로그 개설:
  - **BLOG-01-1**: 블로그 주소와 이름을 입력해 만들고, 소개는 비워 둘 수 있다.
  - **BLOG-01-2**: 주소는 POL-02 규칙을 따르며, 중복이면 입력 단계에서 알린다. 개설 화면에서 "주소는 나중에 바꿀 수 없다"는 사실을 알린다.
  - **BLOG-01-3**: 회원당 블로그는 1개다. 이미 블로그가 있으면 개설을 막는다.
  - **BLOG-01-4**: 개설 후 새 블로그나 글쓰기로 간다.
- **BLOG-02** (P0) 블로그 정보 수정:
  - **BLOG-02-1**: 블로그 이름, 소개, 프로필 이미지를 바꾼다. 주소는 바꿀 수 없다.
  - **BLOG-02-2**: 프로필 이미지가 없으면 기본 이미지를 보여 주고, 소개가 비면 소개 자리를 숨긴다.
- **BLOG-03** (P0) 블로그 메인:
  - **BLOG-03-1**: 그 블로그의 글을 최신순으로 보여 준다(POL-04).
  - **BLOG-03-2**: 각 글에 제목, 발행일, 카테고리, 본문 요약을 보여 준다.
  - **BLOG-03-3**: 글이 없으면 빈 상태를 알리고, 없는 블로그 주소는 404다.
- **BLOG-04** (P0) 사이드바:
  - **BLOG-04-1**: 블로그의 모든 화면(메인, 글 상세, 카테고리·태그 목록)에 같은 사이드바가 붙는다.
  - **BLOG-04-2**: 블로그 이름·프로필(누르면 블로그 메인)과 카테고리 목록·카테고리별 글 수가 필수다.
  - **BLOG-04-3**: '전체 글'은 맨 위, '미분류'는 맨 아래이며, 미분류 글이 없으면 미분류를 숨긴다.
  - **BLOG-04-4**: 볼 수 없는 글은 주인이 아니면 글 수에서 빠진다.
  - **BLOG-04-5**: 선택 구성(P1 이후)으로 태그 목록, 최근 글, 최근 댓글, 인기 글, 방문자 수를 더할 수 있다.

#### POST 글

- **POST-01** (P0) 글 작성·발행:
  - **POST-01-1**: 새 글 쓰기는 빈 상태에서 시작한다.
  - **POST-01-2**: 발행할 때 제목 → 본문 순서로 확인하고 첫 번째 문제를 알린다.
  - **POST-01-3**: 카테고리(하나, 고르지 않으면 미분류), 태그(여러 개), 공개 범위를 정한다.
  - **POST-01-4**: 에디터는 마크다운 입력과 보이는 대로 편집(WYSIWYG)을 함께 제공한다. 어느 쪽으로 써도 문단 제목, 굵게, 목록, 인용, 코드 블록, 링크, 이미지를 표현할 수 있고, 다시 수정하러 열어도 서식이 남는다.
  - **POST-01-5**: 발행하면 글 상세 화면으로 가고, 공감·댓글·조회수는 0에서 시작한다. 발행을 연달아 눌러도 글은 하나만 생긴다.
- **POST-02** (P0) 글 수정:
  - **POST-02-1**: 블로그 주인만 수정하고, 발행 때와 같은 확인(제목·본문 필수)을 거친다.
  - **POST-02-2**: 글 주소, 처음 발행일, 공감·댓글·조회수, 목록 순서는 그대로다.
- **POST-03** (P0) 글 삭제:
  - **POST-03-1**: 블로그 주인만 확인 후 삭제한다. 함께 처리되는 것은 POL-07-1을 따른다.
  - **POST-03-2**: 삭제 후 블로그 메인이나 글 관리 화면으로 간다.
- **POST-04** (P0) 글 상세 조회:
  - **POST-04-1**: 제목, 발행일, 카테고리, 본문, 태그, 공감 수, 댓글을 보여 준다.
  - **POST-04-2**: 볼 수 있는지는 존재 → 소속 블로그 → 블로그 주인 여부 → 공개 범위 순서로 판단하고, 볼 수 없으면 404다.
  - **POST-04-3**: 블로그 주인에게만 수정·삭제가 보인다.
- **POST-05** (P0) 본문 이미지 넣기:
  - **POST-05-1**: 쓰는 위치에 이미지를 넣고, 여러 장을 고르면 고른 순서대로 들어간다. 업로드는 POL-06을 따른다.
- **POST-06** (P0) 공개·비공개 설정:
  - **POST-06-1**: 발행할 때 고르고 발행 후에도 바꿀 수 있다. 노출 규칙은 POL-01을 따른다.

#### CAT 카테고리 · TAG 태그

- **CAT-01** (P0) 카테고리 추가·이름 변경·삭제:
  - **CAT-01-1**: 블로그 주인만 관리하며, 같은 단계 안에서 이름이 겹칠 수 없다.
  - **CAT-01-2**: 삭제하면 그 카테고리의 글은 미분류로 옮긴다. '전체 글'과 '미분류'는 이름을 바꾸거나 지울 수 없다.
  - **CAT-01-3**: 새 블로그는 카테고리 없이 시작한다.
- **CAT-02** (P0) 카테고리별 글 목록:
  - **CAT-02-1**: 그 카테고리의 글만 최신순으로 보여 주고, 카테고리마다 고유한 주소가 있다.
- **TAG-01** (P0) 글에 태그 달기:
  - **TAG-01-1**: 글 하나에 태그를 최대 10개까지 달고, 같은 태그는 한 번만 달린다.
  - **TAG-01-2**: 태그는 블로그 단위로 관리하고, 블로그에 없던 이름을 입력하면 새 태그가 된다.
- **TAG-02** (P0) 태그별 글 목록:
  - **TAG-02-1**: 같은 블로그에서 그 태그가 붙은 글만 보여 주고, 태그마다 고유한 주소가 있다.

#### CMT 댓글 · SOC 반응

- **CMT-01** (P0) 댓글 쓰기·삭제:
  - **CMT-01-1**: 회원만 댓글을 쓰고, 비회원은 로그인으로 안내한다.
  - **CMT-01-2**: 작성자 닉네임과 작성 날짜·시각을 보여 주고, 작성순으로 정렬하며, 글마다 댓글 수를 보여 준다.
  - **CMT-01-3**: 자기 댓글은 확인 후 지운다. 등록을 연달아 눌러도 한 번만 등록된다.
- **CMT-02** (P0) 블로그 주인의 댓글 삭제:
  - **CMT-02-1**: 블로그 주인은 자기 블로그 글에 달린 모든 댓글을 지울 수 있지만, 남의 댓글을 수정할 수는 없다.
- **SOC-01** (P0) 공감:
  - **SOC-01-1**: 회원은 글마다 한 번 공감을 누르고, 다시 누르면 취소한다. 비회원은 로그인으로 안내한다.
  - **SOC-01-2**: 공감 수는 바로 반영되고, 새로고침해도 실제 개수와 같다.
  - **SOC-01-3**: 자기 글에는 공감할 수 없다(임시 결정, Assumptions 참고).

#### SRCH 검색 · HOME 홈

- **SRCH-01** (P0) 블로그 내 검색:
  - **SRCH-01-1**: 한 블로그 안에서 제목·본문·태그로 글을 찾고, 영문 대소문자는 구분하지 않는다.
  - **SRCH-01-2**: 검색어의 앞뒤 공백은 빼고 판단하며, 공백만 입력하면 검색하지 않는다.
  - **SRCH-01-3**: 결과는 최신순·페이지 단위이고, 보는 사람이 볼 수 없는 글은 빠진다.
  - **SRCH-01-4**: 결과가 없으면 없다고 알리고 검색어는 남겨 둔다. 검색 결과에도 주소가 있어 새로고침하거나 공유해도 같은 결과가 나온다.
- **HOME-01** (P0) 홈 최신 글:
  - **HOME-01-1**: 플랫폼 전체의 공개 글을 최신순으로 보여 준다. 비공개·구독자 공개 글과 관리자가 숨긴 글·블로그는 빠진다.
  - **HOME-01-2**: 각 글에 제목, 블로그 이름, 발행일, 본문 요약을 보여 주고, 누르면 글 상세로 간다.
  - **HOME-01-3**: 비회원도 볼 수 있고, 더 불러올 때 중복·누락이 없다.

#### ADMIN 서비스 관리

- **ADMIN-01** (P0) 관리자 역할과 전용 영역:
  - **ADMIN-01-1**: 역할은 일반 회원과 서비스 관리자 두 가지이고, 서비스 관리자만 들어가는 관리 영역이 있다. 일반 회원은 403, 비회원은 로그인 안내다.
  - **ADMIN-01-2**: 서비스 관리자는 가입이나 화면으로 될 수 없고 운영자가 지정한다. 서비스 시작 시 관리자 계정이 하나 이상 있다.
  - **ADMIN-01-3**: P0에서는 역할과 영역 보호까지만 구현한다. 실제 관리 기능은 ADMIN-02부터다.

### 기능 요구사항: P1 (권장 24개)

#### AUTH 회원·인증

- **AUTH-03** (P1) 로그인 상태 유지: 브라우저를 닫았다 열어도 로그아웃 전까지 로그인이 유지된다. 만료 후 다시 로그인하면 원래 위치로 돌아온다.
- **AUTH-04** (P1) 블로그 개설 안내: 블로그가 없는 회원이 글쓰기를 누르면 블로그 개설로 안내하고, 블로그가 있으면 글쓰기로 바로 간다.
- **AUTH-05** (P1) 회원정보 수정: 닉네임과 프로필 이미지를 바꾼다. 업로드는 POL-06을 따른다.

#### POST 글

- **POST-07** (P1) 대표 이미지: 본문 이미지 중 하나를 고르거나 따로 올린다. 고르지 않으면 본문 첫 이미지를 쓰고, 이미지가 없으면 대표 이미지 없이 보여 준다.
- **POST-08** (P1) 임시저장: 쓰던 글을 발행하지 않고 저장했다가 이어 쓴다. 블로그 주인에게만 보인다. 새 글 쓰기를 열 때 임시저장된 글이 있으면 이어 쓸지 묻고, 발행하면 그 임시저장은 지워진다.
- **POST-09** (P1) 조회수: 글을 열면 조회수가 오른다. 같은 사람이 짧은 시간 안에 다시 열면 세지 않는다(임시 결정).
- **POST-10** (P1) 이전·다음 글: 같은 블로그 안에서 발행 순서로 앞뒤 글로 이동하고, 보는 사람이 볼 수 없는 글은 건너뛴다.
- **POST-11** (P1) 주제 지정: 블로그마다 플랫폼 주제 목록에서 하나를 고르고, 그 블로그의 모든 공개 글이 그 주제로 묶인다. 고르지 않으면 '주제 없음'이고 홈 주제별 글에서 빠진다. 주제는 카테고리와 별개다.

#### CAT 카테고리 · TAG 태그

- **CAT-03** (P1) 하위 카테고리: 한 단계까지만 둔다. 하위가 있는 상위는 바로 지울 수 없다. 상위를 고르면 하위 글까지 보이고 글 수도 합친 값이다. 상위가 다르면 같은 이름을 쓸 수 있다.
- **CAT-04** (P1) 카테고리 순서 변경: 블로그 주인이 정한 순서대로 사이드바에 보인다.
- **TAG-03** (P1) 태그 목록: 블로그에서 쓴 태그를 모아 보여 주고, 누르면 태그별 글 목록으로 간다.

#### CMT 댓글 · SOC 반응

- **CMT-03** (P1) 댓글 수정: 자기 댓글만 수정할 수 있다.
- **CMT-04** (P1) 방명록: 회원이 블로그에 방명록을 남긴다. 쓰기·삭제 규칙은 댓글과 같고, 블로그 주인은 모든 방명록을 지울 수 있다.
- **SOC-02** (P1) 공유: 바뀌지 않는 글 주소(POL-03)를 복사할 수 있다.

#### SUB 구독·피드

- **SUB-01** (P1) 블로그 구독·해제: 다른 블로그를 구독하고 해제한다. 자기 블로그는 구독할 수 없다. 구독 상태가 버튼에 보이고, 내 구독 목록에서 해제할 수 있다.
- **SUB-02** (P1) 구독 피드: 구독한 블로그의 새 글을 최신순으로 모아 보여 준다. 볼 수 없는 글은 빠지고, 더 불러올 때 중복·누락이 없다. 구독이 없으면 그 사실을 알리고 다른 블로그 둘러보기로 안내한다.
- **SUB-03** (P1) 구독자 수: 블로그에 구독자 수를 보여 주고, 새로고침해도 실제 값과 같다.

#### SRCH 검색 · HOME 홈

- **SRCH-02** (P1) 통합 검색: 플랫폼 전체에서 공개 글과 이용 제한되지 않은 블로그(이름·소개)를 찾는다. 글 결과에 어느 블로그의 글인지 보인다. 검색어·빈 결과 처리는 SRCH-01과 같다.
- **HOME-02** (P1) 인기 글: 최근 7일 동안 받은 공감 수와 댓글 수의 합으로 공개 글 순위를 매긴다. 숨긴 글은 빠진다. 인기 글이 없으면 빈 상태를 알리거나 최신 글로 대신한다.
- **HOME-03** (P1) 주제별 글: 주제를 고르면 그 주제의 공개 글을 최신순으로 보여 준다. 주제가 없는 글은 어느 주제에도 나오지 않고, 주제마다 고유한 주소가 있다.

#### MNG 블로그 관리

- **MNG-01** (P1) 내 글 관리: 내 블로그의 공개·비공개·임시저장 글(POST-12를 구현하면 구독자 공개 글도)을 상태별로 구분해 모아 본다. 여기서 수정·삭제·공개 범위 변경을 하고, 관리자가 숨긴 글은 숨김 상태와 사유가 보인다.
- **MNG-02** (P1) 댓글 관리: 내 블로그의 댓글과 방명록을 최신순으로 모아 보고 지운다. 각 댓글이 어느 글에 달렸는지 보인다.

#### ADMIN 서비스 관리

ADMIN 공통 원칙(P1·P2 모두): 제재는 삭제가 아니라 숨김·제한이고, 해제하면 원래 상태(위치, 수치, 주소)로 돌아간다. 제재할 때 사유를 반드시 남기고, 대상자는 그 사유를 볼 수 있다. 남의 내용은 수정할 수 없고, 다른 서비스 관리자를 제재할 수 없다.

- **ADMIN-02** (P1) 회원 이용 제한: 기간(정한 날짜까지 또는 영구)과 사유를 정해 회원을 제한한다. 제한된 회원은 로그인할 수 없고 사유·기한을 안내받으며, 이미 로그인한 상태였다면 다음 행동부터 막힌다. 기한이 지나면 자동으로 풀리고, 관리자가 미리 풀 수도 있다. 제한 기간에도 그 회원의 블로그는 그대로 보인다(임시 결정).
- **ADMIN-03** (P1) 게시물 숨김: 사유를 정해 글·댓글을 숨기고 되돌린다. 숨긴 글은 목록·검색·홈·피드·글 개수에서 빠지고 다른 사람에게 404다. 글쓴이에게는 숨김 사실과 사유가 보인다. 숨긴 댓글은 '관리자가 숨긴 댓글'로 표시되고 답글은 남는다.

### Key Entities

- **회원**: 서비스에 가입한 사람. 닉네임, 프로필 이미지, 역할(일반 회원·서비스 관리자), 카카오 계정 연결, 탈퇴 여부를 가진다.
- **블로그**: 회원 한 명이 개설한 개인 공간(회원당 1개). 주소(변경 불가, 영구 예약), 이름, 소개, 프로필 이미지, 주제, 스킨·배경, 이용 제한 상태를 가진다.
- **글**: 블로그에 속한 게시물. 제목, 본문, 글 주소(제목 기반, 불변), 카테고리(없으면 미분류), 태그, 대표 이미지, 공개 범위(공개·비공개·구독자 공개), 상태(임시저장·예약·발행), 처음 발행 시각, 조회수, 댓글 허용 여부, 관리자 숨김 상태와 사유를 가진다.
- **카테고리**: 블로그 주인이 만든 분류. 이름, 순서, 상위 카테고리(한 단계까지), 비공개 여부를 가진다. '전체 글'과 '미분류'는 고정된 자리다.
- **주제**: 플랫폼이 정한 큰 분류(IT, 여행 등). 블로그마다 하나를 지정한다.
- **태그**: 블로그 단위 키워드. 글과 여러 대 여러로 연결되며 글당 최대 10개다.
- **이미지**: 회원이 올린 이미지 파일. 형식(jpg, png, gif, webp)과 크기를 가지며 글 본문·대표 이미지·프로필·배경에 쓰인다.
- **댓글**: 글에 회원이 남긴 의견. 작성자, 내용, 작성 시각, 답글 관계(한 단계), 비밀 여부, 삭제·관리자 숨김 상태를 가진다.
- **방명록**: 블로그에 회원이 남긴 글. 작성자, 내용, 작성 시각을 가진다.
- **공감 / 저장**: 회원과 글의 관계. 회원당 글마다 한 번만 존재한다.
- **구독**: 회원과 블로그의 관계. 자기 블로그는 대상이 될 수 없고, 서로 구독하면 맞구독으로 보인다.
- **알림**: 회원이 받는 서비스 안 알림. 종류(댓글·공감·구독·새 글), 행위자, 관련 글·댓글, 읽음 여부를 가진다.
- **제재 기록**: 회원 이용 제한(기간·사유·해제), 블로그 이용 제한, 글·댓글 숨김과 그 이력. 이력은 수정·삭제할 수 없다.
- **신고**: 회원이 남의 글·댓글을 사유를 골라 신고한 기록과 처리 결과(대기·숨김·기각).
- **공지 / 방문 통계 / 차단·금칙어**: 관리자 공지, 블로그별 날짜별 방문자 수, 블로그별 차단 회원과 금칙어.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 처음 온 사용자가 가입부터 첫 글 발행까지 5분 안에 마친다.
- **SC-002**: P0 기능 24개가 모두 위 수락 시나리오대로 동작하고, "가입 → 블로그 개설 → 글 발행 → 다른 사람이 홈에서 발견 → 읽기·댓글·공감" 흐름을 처음부터 끝까지 막힘 없이 시연할 수 있다.
- **SC-003**: 권한표(COM-01)의 모든 행동을 네 가지 사용자 상태로 화면 조작, 주소 직접 입력, 직접 요청의 세 경로에서 시도했을 때 100% 같은 결과(허용·로그인 안내·403·404)가 나온다.
- **SC-004**: 남의 비공개 글·구독자 공개 글이 볼 수 없는 사람의 목록, 검색, 홈, 인기 글, 피드, 사이드바, 글 개수에 한 번도 나타나지 않는다.
- **SC-005**: 발행·댓글·공감·구독 버튼을 1초 안에 10번 눌러도 결과는 각각 1건이다. 새로고침 후 모든 개수가 실제 값과 같다.
- **SC-006**: 글 목록과 글 상세 화면은 사용자의 95%가 2초 안에 내용을 보기 시작한다. 공감·구독 버튼은 누른 즉시(체감상 기다림 없이) 상태가 바뀐다.
- **SC-007**: 스크립트를 넣은 제목·본문·댓글·블로그 이름·닉네임이 어떤 화면에서도 실행되지 않는다(테스트한 입력 100% 차단).
- **SC-008**: 360px 폭 휴대폰 화면에서 P0 기능 24개를 가로 스크롤 없이 모두 쓸 수 있고, 최신 크롬·사파리·엣지에서 같은 결과가 나온다.
- **SC-009**: 저장 실패와 로그인 만료 상황을 10번 만들었을 때, 쓰던 제목·본문·댓글을 한 번도 잃지 않는다.
- **SC-010**: 제목을 수정한 글과 오래된 글의 공유 주소가 100% 그대로 열린다.

## Assumptions

- **선택 항목**: 원본 요구사항 명세서에 적힌 서현의 방향(카카오 로그인, 블로그 1개, 서브도메인, 혼합 에디터, 제목 기반 글 주소, 7일 공감+댓글 인기 기준, 블로그마다 주제, 구독자 공개)을 이 저장소 서비스의 결정으로 적용했다. 다른 방향을 고르면 [선택 항목](#선택-항목-이-서비스의-결정) 표와 해당 요구사항을 함께 고친다.
- **미결정 사항의 임시 결정**: 팀 명세서 9.2의 미결정 사항은 팀에서 정하기 전까지 아래처럼 임시로 정한다. 팀 결정이 나면 이 목록과 관련 요구사항을 고친다.
  - 글자 수: 기준안(글 제목 100자, 블로그 이름 40자, 카테고리 이름 20자)을 쓴다.
  - 회원 탈퇴 후 처리: 블로그·글·댓글을 '탈퇴한 회원'으로 남기고 개인정보만 지운다(AUTH-06).
  - 조회수 중복: 같은 사람이 짧은 시간 안에 다시 열면 세지 않는다(POST-09). 시간 간격은 설계 단계에서 정한다.
  - 자기 글 공감: 허용하지 않는다(SOC-01-3). 인기 글 순위를 스스로 올리는 것을 막기 위함이다.
  - 이용 제한 회원의 블로그: 제한 기간에도 그대로 보인다(ADMIN-02).
  - 블로그 1개일 때 재개설: 삭제 후 다른 주소로 새로 개설할 수 있다(BLOG-07).
  - 주제 목록: 세 서비스가 같은 주제 목록(IT, 여행 등)을 쓴다고 가정한다.
- **각자 정하는 값**: 업로드 크기 상한, 로그인 유지 기간, 조회수 중복 판단 시간, 인기 글 갱신 주기, 추천·인기 블로거 기준, 방문자 집계 방식, 기본 이미지와 스킨 종류는 `/speckit-plan` 단계의 설계 문서에서 정한다.
- **범위 밖**: 광고·결제, 모바일 앱, 이메일·푸시 알림, 개인 도메인 연결, 스킨 HTML·CSS 직접 편집, 비회원 댓글, 이메일 로그인(카카오만 쓰므로 이메일 인증·비밀번호 재설정도 없음).
- **팀 명세서에서 제외된 기능**: 반려동물 전용 기본 카테고리('일상', '산책', '성장일기'), 한옥 테마 등은 이 명세에 넣지 않았다. 구현하려면 별도 기능으로 명세에 추가한다.
- **데이터 모델**: 팀 ERD(기본안)는 `/speckit-plan` 단계의 `data-model.md`에서 위 Key Entities와 맞춰 쓴다.
- **사용 환경**: 사용자는 최신 데스크톱·휴대폰 브라우저로 접속하며, 카카오 계정을 가지고 있다.
